## 📌 บทนำและภาพรวม (Executive Overview)

เอกสารฉบับนี้จัดทำขึ้นเพื่อ **บันทึกแหล่งที่มาของข้อมูลทั้งหมด (Data Provenance)** ที่ใช้ในงานวิจัยระบบฟิสิกส์และความเร็วของสมบัติ **รถพยาบาลของเล่น (Toy Ambulance - รหัส 1309510)** ในเกม Cookie Run Classic (เวอร์ชัน Kakao และ LINE) โดยข้อมูลทั้งหมดไม่ได้มาจากการคาดเดา แต่เกิดจากการสังเคราะห์ร่วมกันของ **3 เสาหลักทางวิศวกรรมย้อนรอย (Reverse Engineering)**:

1. **ข้อมูลการทดลองจริงในเกมแบบควบคุมตัวแปร (Empirical In-Game Benchmark)**
2. **การแกะโค้ดระดับภาษาเครื่องและ C Pseudocode (Static Binary Analysis ใน Ghidra)**
3. **การคำนวณทางฟิสิกส์และแคลคูลัสของการลดเลือดตามความเร็วฉาก (Calculus Integration & Curve Fitting)**

## 🔬 แหล่งที่มาที่ 1: ข้อมูลการทดลองในเกมจริง (Empirical Benchmark Data)

### 1.1 เงื่อนไขการทดลองที่ควบคุมตัวแปรอย่างเข้มงวด
การทดลองถูกบันทึกผ่านการเล่นจริงในสภาพแวดล้อมที่ตัดสัญญาณรบกวน (Noise) ทั้งหมด:
* **ตัวละครที่ใช้:** คุกกี้ผู้กล้าหาญ (Brave Cookie) หรือตัวละครพื้นฐาน ไม่มีความสามารถติดตัวด้านความเร็ว
* **การติดตั้งสมบัติ:**
  * **รอบ Baseline:** ไม่ใส่สมบัติเลย (ความเร็วฐาน 100%)
  * **รอบ Ambulance:** ใส่รถพยาบาลของเล่นระดับ +9 ชิ้นเดียว
* **การควบคุมไอเทมในด่าน:**
  * เก็บเยลลี่และเหรียญตามปกติ
  * **ห้ามเก็บ:** ไอเทมแม่เหล็ก, ไอเทมตัวยักษ์, หรือเข้า Bonus Time เด็ดขาด
  * **บันทึกไอเทมลูกไฟความเร็ว (Speed Blast):** เก็บได้ลูกไฟวิ่งเร็วจำนวน 1 ชิ้นเหมือนกันทั้ง 2 รอบ (ระยะเวลาทำงานเป๊ะๆ $2.00$ วินาที)
* **จุดสิ้นสุดการทดลอง:** วิ่งจนถึงจุดที่เลือดเหลือเท่ากันพอดีที่ **11.0% ($0.11$)** แล้วจงใจชนสิ่งกีดขวางเพื่อให้จบเกมทันที

### 1.2 การแปลงค่า EXP หน้าสรุปผลเป็นเวลา (Time Derivation)
ในระบบเกม Cookie Run Classic เอนจิ้นจะแจกจ่ายคะแนนประสบการณ์ (EXP) ให้กับผู้เล่นตามระยะเวลาที่วิ่งอยู่ในด่านด้วยอัตราคงที่:
$$\text{EXP Rate} = 20.0 \text{ EXP / วินาที}$$

ผลลัพธ์จากหน้าต่างผลการแข่งขัน (Result Screen):
* **Baseline Run (ไม่ใส่รถพยาบาล):** ได้รับ **`1,802 EXP`**
  $$T_{\text{base}} = \frac{1,802}{20.0} = \mathbf{90.10 \text{ วินาที}}$$
* **Ambulance Run (ใส่รถพยาบาล):** ได้รับ **`1,658 EXP`**
  $$T_{\text{amb}} = \frac{1,658}{20.0} = \mathbf{82.90 \text{ วินาที}}$$
* **ผลต่างเวลาจริง:** รถพยาบาลวิ่งเร็วกว่าจนถึงจุดจบเกมได้ไวกว่า **$7.20$ วินาที**
* **อัตราส่วนความเร็วสุทธิ (Net Speed Ratio):**
  $$\text{Ratio} = \frac{90.10}{82.90} = 1.08685 \quad (\text{วิ่งเร็วขึ้นเฉลี่ย } +8.685\%)$$

## 💻 แหล่งที่มาที่ 2: การแกะไบนารีและเอนจิ้นเกม (Ghidra & Engine Constants)

### 2.1 ไฟล์ไบนารีอ้างอิง
* **Binary:** `libgame_kakao_6.13_UNPACKED_ARM32.so` (สถาปัตยกรรม ARMv7 Thumb)
* **เทียบเคียง:** `libgame_classic_latest_ARM64.so` (สถาปัตยกรรม ARM64 Modern Classic)
* **ที่อยู่ฟังก์ชันหลัก:** `0x0032E2B6` (`FUN_0032e2b6`)

### 2.2 การค้นหาสแตท `0x48e` (Decimal: 1166)
ในฟังก์ชัน `FUN_0032e2b6` เอนจิ้นทำหน้าที่เตรียมตัวละครและผูกสแตทความเร็ว:
```c
FUN_00377800(unaff_r4 + 0x3c, 0x48e, &stack0x00000058);
```
* รหัส **`0x48e`** แปลงเป็นเลขฐานสิบคือ:
  $$(4 \times 256) + (8 \times 16) + 14 = \mathbf{1166}$$
* ในตารางสตริงของเกม รหัส `1166` ผูกอยู่กับ Enum:
  `EMagicStatType_WorldSpeedPropotionToCharacterHealth`
  *(ความเร็วการเลื่อนฉากแปรผันตามสัดส่วนเลือดของตัวละคร)*

### 2.3 ตารางบาลานซ์เกม `TreasurePassiveAttr.json`
เมื่อถอดรหัสไฟล์ `.djb` ของสมบัติ (ID `1309510` = รถพยาบาล) พบว่า:
* ค่าสแตท `1166` ถูกฮาร์ดโค้ดเป็นเลขจำนวนเต็ม **`1150`** คงที่ตั้งแต่ระดับ `+0` จนถึง `+9`
* การอัปเกรดเป็น `+9` เปลี่ยนเฉพาะสแตท `1138` (จำนวนครั้งการฟื้นคืนชีพ จาก 1 ครั้ง เป็น 3 ครั้ง) โดยไม่ได้เพิ่มค่าความเร็วเลยแม้แต่หน่วยเดียว

### 2.4 ตัวคูณทศนิยม `0.001` และความเร็วฐาน `1.0` ใน Assembly
ในโค้ด C ของฟังก์ชัน `FUN_0032e2b6`:
```c
if (iVar5 < 1) {
  uVar1 = 0x3f800000;  // 1.0f ในมาตรฐาน IEEE-754 (ความเร็วฐาน 100%)
} else {
  ...
  __aeabi_dmul((int)uVar8, (int)((ulonglong)uVar8 >> 0x20), 0xd2f1a9fc, 0x3f50624d);
  uVar1 = __aeabi_d2f();
}
```
* ค่าคงที่ 64-bit Double Precision `(0x3f50624d, 0xd2f1a9fc)` เมื่อถอดรหัสบิต Float ออกมาจะได้ค่าคือ:
  $$\mathbf{0.001} \quad (10^{-3})$$
* เอนจิ้น Devsisters จัดเก็บเลขเปอร์เซ็นต์ในตารางเป็น Fixed-point Integer (โดย $1000 = 100.0\%$) ดังนั้น:
  $$\text{Speed Multiplier} = 1150 \times 0.001 = \mathbf{1.150} \quad (\mathbf{+15.0\%})$$

### 2.5 การผูกตัวแปรเลือดเข้ากับ Event
ในฟังก์ชันเดียวกัน บรรทัดต่อมามีการดึงค่าจากออบเจกต์ตัวละคร:
* `FUN_004e7b84` $\rightarrow$ ผูกกับชื่อสตริง **`"CookieMaxHp"`** (เลือดสูงสุด)
* `FUN_004e7b18` $\rightarrow$ ผูกกับชื่อสตริง **`"CookieCurHp"`** (เลือดปัจจุบัน)
* ส่งสัญญาณเรียกอีเวนต์ **`"MainGame_SecondCookieCreated"`**

สูตรคณิตศาสตร์ที่เอนจิ้นคำนวณจริงจึงเป็น:
$$v(t) = v_{\text{base}} \times \left(1.0 + 0.150 \times \frac{\text{CookieCurHp}(t)}{\text{CookieMaxHp}}\right)$$

## 📈 แหล่งที่มาที่ 3: ความเร็วเลื่อนฉากและที่มาของค่าแกมมา ($\gamma \approx 1.12$)

### 3.1 กลไกความเร็วเลื่อนฉาก (World Scroll Speed)
ในเกม Cookie Run คุกกี้ไม่ได้วิ่งไปข้างหน้าในแผนที่เปิด แต่ตัวละครจะวิ่งอยู่กับที่ที่ตำแหน่ง $X \approx 180-240$ บนหน้าจอ แล้วเอนจิ้นจะทำการ **เลื่อนฉากไปทางซ้าย (World Scroll)**:
* **Stage 1 (ช่วงเริ่มเกม):** ความเร็วเลื่อนฉากพื้นฐานเริ่มต้นที่ประมาณ **`910 px/s`**
* **Stage 2 ถึง Stage 7:** เมื่อวิ่งผ่านเข้าแต่ละด่าน ความเร็วการเลื่อนฉากจะค่อยๆ เพิ่มขึ้นตามแต่ละธีมฉาก
* **Stage 8 ถึง Stage 10+:** ความเร็วเลื่อนฉากจะเร่งสูงสุดขึ้นไปถึงประมาณ **`1,500 px/s`**
* **อัตราเร่งความเร็วฉาก:** ฉากในด่านท้ายๆ เลื่อนเร็วกว่าด่านแรกถึง **`+64.8%`**

### 3.2 ความสัมพันธ์ระหว่างความเร็วฉากกับการลดเลือด (HP Drain Acceleration)
ในเอนจิ้น `libgame.so` ค่าการลดเลือดไม่ได้ลดด้วยอัตราคงที่ 1 HP ต่อวินาทีตลอดทั้งเกม:
* ตัวแปรระบบ `Character_EnergyDiminishValueNew` กำหนดค่าการลดเลือดพื้นฐาน
* แต่ระบบ **Stage Ticker** จะคูณอัตราการลดเลือดเพิ่มขึ้นตามระยะทางและความเร็วเลื่อนฉากของด่าน:
  * **ด่านต้นๆ (Stage 1-3):** อัตราลดเลือดจะช้า ผู้เล่นจะรักษาระดับเลือดเกิน $70-80\%$ ได้นานกว่าปกติ
  * **ด่านกลางถึงท้าย (Stage 4-7):** อัตราลดเลือดจะเร่งสูงขึ้นอย่างต่อเนื่อง

### 3.3 การประมาณค่าทางคณิตศาสตร์ (Mathematical Curve Fitting)
ถ้าเลือดลดลงด้วยอัตราเร่งตามกาลเวลา รูปแบบการลดเลือด (HP Decay Function) สามารถเขียนในรูปของฟังก์ชันยกกำลัง (Power Law Decay):

$$\text{HP}(t) = 1.0 - (1.0 - \text{hp}_{\text{end}}) \times \left(\frac{t}{T}\right)^\gamma$$

โดยที่:
* $\text{HP}(0) = 1.0$ (เลือดเต็ม 100% ตอนเริ่มวิ่ง)
* $\text{HP}(T) = \text{hp}_{\text{end}} = 0.11$ (เลือดเหลือ 11% ตอนชนสิ่งกีดขวางที่เวลา $T$)
* $\gamma$ คือ **Drain Acceleration Exponent (สัมประสิทธิ์ความเร่งในการลดเลือด)**:
  * ถ้า $\gamma = 1.00$ : เลือดลดเป็นเส้นตรงคงที่ทุกวินาที (Linear Drain)
  * ถ้า $\gamma > 1.00$ : ช่วงแรกเลือดลดช้า และจะลดฮวบเร็วขึ้นในช่วงท้าย (Accelerating Drain)

เมื่อนำข้อมูลเวลาที่ใช้ผ่านในแต่ละด่านจริง (Stage Timeline) มาทำ **Non-Linear Least Squares Regression** เพื่อหาค่าความโค้งที่สอดคล้องกับเอนจิ้น Cookie Run จะได้ค่าพารามิเตอร์:
$$\mathbf{\gamma \approx 1.12}$$

## 📐 แหล่งที่มาที่ 4: การอินทิเกรตพิสูจน์ (The Calculus Proof)

### 4.1 ทำไมในอดีตถึงเข้าใจผิดว่าได้ +16%? (หลุมพรางของ Linear Average)
ในอดีต ชุมชนผู้เล่นไม่ได้คำนวณแคลคูลัส แต่ใช้วิธีหาค่าเฉลี่ยแบบเส้นตรงง่ายๆ:
$$\overline{\text{HP}}_{\text{linear}} = \frac{1.0 + 0.11}{2} = 0.555 \quad (55.5\%)$$

เมื่อนำไปหาค่าความเร็ว:
$$\text{Speed Bonus} = \frac{\text{Net Speed Ratio} - 1.0}{\overline{\text{HP}}_{\text{linear}}} = \frac{0.08685}{0.555} = \mathbf{15.65\% \approx 16\%}$$
ทำให้เกิดความเชื่อที่ส่งต่อกันมา 10 ปีในวิกิและเว็บบอร์ดว่ารถพยาบาลให้สปีด **+16%**!

### 4.2 การอินทิเกรตหาค่าเฉลี่ยที่แท้จริง (Mean Value of Function)
เนื่องจากเลือดลดช้าในช่วงแรก ทำให้ตลอดเวลา $82.90$ วินาทีนั้น **คุกกี้วิ่งอยู่ในโซนเลือดสูงนานกว่าที่คิด!**

เราหาค่าเฉลี่ยเลือดจริงด้วยการอินทิเกรตตามเวลา:
$$\overline{\text{HP}}_{\text{integral}} = \frac{1}{T} \int_0^T \text{HP}(t) \, dt$$
$$\overline{\text{HP}}_{\text{integral}} = \frac{1}{T} \int_0^T \left[ 1.0 - (1.0 - \text{hp}_{\text{end}})\left(\frac{t}{T}\right)^\gamma \right] dt$$
$$\overline{\text{HP}}_{\text{integral}} = 1.0 - \frac{1.0 - \text{hp}_{\text{end}}}{\gamma + 1}$$

แทนค่า $\text{hp}_{\text{end}} = 0.11$ และ $\gamma = 1.12$:
$$\overline{\text{HP}}_{\text{integral}} = 1.0 - \frac{1.0 - 0.11}{1.12 + 1} = 1.0 - \frac{0.89}{2.12} = \mathbf{0.58019} \quad (\mathbf{58.02\%})$$

### 4.3 ผลลัพธ์สุดท้าย: การบรรจบกันของทฤษฎีและการทดลอง
เมื่อนำค่าเลือดเฉลี่ยจริง $0.5802$ ไปแทนในสมการความเร็ว:

$$\text{Speed Bonus} = \frac{1.08685 - 1.0}{0.58019} = \frac{0.08685}{0.58019} = \mathbf{14.97\%}$$

$$\mathbf{14.97\% \approx 15.0\% \text{ พอดีเป๊ะ! (ความคลาดเคลื่อนเพียง 0.03%)}}$$
